# Валидатор смысла: статус и план

Живой документ для команды. Что мы строим на понятийной сети, что уже работает, какие
честные числа получили на реальных данных, и куда идём дальше. Принципы держим те же:
**детерминизм, аудируемость, held-out/реальностный замер, доменный скоуп, без галлюцинаций.**
Контекст: [идея понятийной сети](ИДЕЯ-понятийной-сети.md),
[роадмап](ROADMAP-понятийная-сеть-и-язык.md).

## Тезис в одном абзаце
Поверх понятийной сети мы собрали **детерминированный валидатор смысла**: две фразы (исходник
и перевод, в т.ч. на разных языках) разбираются в язык-независимый граф понятий, графы
сравниваются по отпечатку, и выдаётся **триаж из трёх состояний** — ✅ эквивалентно /
⚠️ расхождение (с классом) / ❓ непроверяемо. Это не «ещё один чат по тексту» — это слой
**гарантии**, которого у LLM нет по природе: детерминизм, доказуемость, отсутствие
галлюцинаций по построению, аудит-след.

## Где реальное преимущество над LLM (и где его нет)
Честно: задачу «загрузил книгу — спрашиваю свободным языком» LLM уже решает хорошо. В лоб мы
её не обыгрываем. Преимущество — только там, где LLM проигрывает **структурно**, а не «пока
не умеет»:
- **детерминизм** — один вход даёт один ответ;
- **доказуемость** — ответ это путь по графу, его можно предъявить аудитору;
- **без галлюцинаций по построению** — система не выдумывает фактов, которых нет в графе;
- **аудит** — не «модель так подумала», а проверяемая цепочка.

Поэтому продукт — **не «отвечать лучше», а детерминированный гард для опасных структурных
claim'ов** (числа, единицы, отрицание, сущности/отношения) — ровно тех, где LLM-судьи слабее
всего, а цена ошибки выше всего (медицина, регуляторика, safety).

**Честные пределы (не замалчиваем):**
- Универсальный «детектор галлюцинаций» невозможен в принципе: без эталона истины нет
  проверки. Реально — проверка *заземлённости* против данного источника / онтологии.
- Детерминированный валидатор над свободным текстом силён ровно настолько, насколько
  покрывает парсер. Если извлекать графы через LLM — детерминизм покрывает только шаг
  сравнения, не понимание. Сильнее всего — узкий домен с контролируемым языком.

## Что построено (всё в `develop`, тесты зелёные)
Пайплайн `text → граф понятий → text` и валидатор поверх него, модульно по доменам:

- **Понятийная сеть**: ~4500 понятий (ядро + WordNet-слой), типы/аффордансы с наследованием,
  отношения с селективными ограничениями, валидация (категориальные ошибки отвергаются).
- **Round-trip / перевод через смысл** (`parse.py`, `roundtrip.py`, `render.py`): локативы,
  переходные, made_of, **прилагательные**, **императивы** («Открой файл»), **отрицание**
  («не закрывай окно»), **числа** («два файла»), **единицы** («5 мл воды»). RU↔EN, инвариантно
  к порядку слов и языку входа. Текстовый рендер графа с полярностью/количеством/мерой.
- **Отпечаток ситуации** (`situation.py`): язык-независимый id, в который входят **полярность
  (¬), количество (×N), мера ({5ml}), признаки** — значит «open file» ≠ «not open file» ≠
  «two files» ≠ «5 ml» ≠ «5 mg» по id. Это и есть ядро валидатора.
- **Вопросы к сети** (`ask.py`): «что на столе?», «съедобно ли X?», «из чего стол?» —
  ответ из памяти/онтологии; петля «сказал → запомнилось → спросил».
- **Валидатор** (`equivalence.py`): триаж + классы расхождения (polarity / quantity / unit /
  attribute / structure). Целостность: «эквивалентно» НИКОГДА не выдаётся, если сторона не
  разобрана.
- **Домены** (модульными паками): софт/UI (`software_domain.py` — file/window/button/…,
  действия open/save/delete/show/configure/copy/install/…, императивы); общий бытовой слой.
- **Запуск**: `demo-meaning.cmd` (round-trip), `check-demo.cmd` (валидатор), в чате `/meaning`,
  `/demo`, `/check A | B`. Реальностный замер — `python -m casa.curriculum.reality_check`.

## Тест реальности (числа, не слова)
`reality_check.py` меряет два числа, решающих «есть ли продукт»:
- **Recall на опасных классах** — на разбираемых парах ловим ли внесённые ошибки (потерянное
  «не», 5↔50, мл↔мг). **100%** на всех прогонах (polarity/quantity/unit).
- **Покрытие** — на какой доле реальных пар строим граф с обеих сторон.

| Набор | Покрытие | Recall |
|---|---|---|
| Курируемый (контролируемые формы) | **100%** | 100% |
| Сырой OPUS KDE4 en-ru (worst-case UI-текст) | 0.3% → 1.7% → **2.7%** | 100% |

**Вывод:** ядро незыблемо (recall 100%); покрытие сырого текста — грайнд (~+1%/батч, тяжёлый
хвост: RU генитивные компаунды, предложные дополнения, слэши/скобки). KDE — worst-case;
жизнеспособность держится на том, **контролируемый ли текст в целевом домене** (на
контролируемых формах у нас 100%). Медицинские этикетки контролируемее KDE.

## Что дальше — развилка (стратегическая, не инженерная)
Дальнейший грайнд сырого текста — низкая отдача. Реальные пути:
- **A. Узкий домен end-to-end** — построить онтологию + формы целевого домена (медэтикетки /
  софт-хелп) и показать высокое покрытие на *его* реальном тексте. Это доказывает продукт-путь.
- **B. LLM-фронт (гибрид)** — LLM извлекает граф из свободного текста, детерминированное ядро
  сравнивает/валидирует. Покрытие взлетает ценой сужения гарантии до шага сравнения.
- **C. Зафиксировать research-PoC** — тезис доказан; масштабирование покрытия — честно
  обозначенная будущая работа.

**Ближайшие конкретные рычаги** (если двигаем покрытие софт-домена):
1. RU генитивные компаунды («файл пиктограммы» — голова первая) — самый частый класс промахов.
2. Предложные дополнения действий («скопировать в буфер»).
3. Целевой реальностный замер на настоящем медицинском IFU (нужна мини-онтология домена).

## Принципы (что держим во всём)
- Детерминизм и аудируемость — каждый вывод это путь по графу, его можно показать.
- Реальностный замер — покрытие и recall меряем на реальных парах, а не на заготовках.
- Доменный скоуп — точность в узком домене важнее охвата открытого мира.
- Честные границы — что курируется vs где потолок (парсинг свободного текста); без галлюцинаций.
