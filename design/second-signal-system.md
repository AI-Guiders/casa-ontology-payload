# Вторая сигнальная система (ССС) — подсистема CASA

**Status:** lab — `tools/sss_*`, store `lab/agent-stores/lexicon-lab`  
**Date:** 2026-05-28  
**Не называть:** «Bukvar Encode», «ещё один codec для KB»  
**См.:** [`bukvar-text-modality.md`](bukvar-text-modality.md) (педагогическая лестница), [`casa-layout.md`](casa-layout.md)

## Одна фраза

**ССС** — отдельная подсистема цилиндра: знаки (буква → слог → слово → высказывание), которые **стоят за** переживаниями первой сигнальности (ощущения, образы, действия), а не дублируют внешний markdown.

Классика (Павлов / культурно-историческая школа): **первая** сигнальная система — прямые сигналы среды; **вторая** — сигналы **о** сигналах (речь, письмо). У нас это **не метафора ради красоты**, а **граница подсистем** в layout и hot path.

## Две подсистемы на одном цилиндре

> **Расширение:** несколько цилиндров — `prism_memory` + `prism_hippo` (стек H0…H3, консолидация). См. [`multi-cylinder-memory.md`](multi-cylinder-memory.md), [`hippo-lattice-stack.md`](hippo-lattice-stack.md).

```text
┌─────────────────────────────────────────────────────────┐
│  ССС (вторая сигнальность)     │  SN / CEN              │
│  L0..L3: **целые решётки** по z │  маршрут: active_lattice│
│  + z-мосты compose между ними  │  babble/correct         │
├───────────────────────────────┴─────────────────────────┤
│  Первая сигнальность (roadmap)  │  math.* палочки, vis.* │
│  — ощущение, образ, операция    │  Exp L, не в ССС       │
└─────────────────────────────────────────────────────────┘
         один буфер (x,y,z), разные регионы и контракты
```

| | Первая СС (roadmap) | Вторая СС (ССС, v0 зачаток) |
|---|---------------------|------------------------------|
| **Носитель** | `vis.*`, `math.*`, сенсомоторика | `grapheme.*`, `syllable.*`, `lang.word.*`, `ru.dialog.*` |
| **Связь** | «вижу / делаю» | знак **указывает на** кластер первой СС (позже `E:` hub) |
| **Память** | свой слой/домен в DMN | **стек решёток** `L0..L3` + **z-мосты** ([`sss-multi-lattice-z.md`](sss-multi-lattice-z.md)); v0 lab — полосы [`layout.v1.json`](layout.v1.json) как stub |
| **Ошибка** | путать с ingest grammar KB | называть encode «букварём» |

## Зачаток в lab (имена файлов — временные)

Код пока с префиксом `bukvar_*` — **scaffold**, не канон. Смысл:

| Scaffold | Роль ССС |
|----------|----------|
| `bukvar_codec.py` | размещение **знаков** по слоям цилиндра (не «encode учебника») |
| `bukvar_field.py` | персистентный **снимок ССС** в `field_state` (`codec: sss`) |
| `bukvar_surface.py` | продукция со **второй** сигнальности (surface), без `claim.text` |
| `layout.v1.json` | **interim:** y-полосы на одной плоскости |
| `prisms/memory/stack.json` | **цель:** отдельная решётка на `z_level`, z-мосты |

Целевые имена (когда стабилизируем): `sss_codec`, `memory_field`, `sss_surface`, store `lexicon-lab`.

## Что ССС делает и не делает

**Делает:**

- накапливает **структуру знаков** в цилиндре (слои B0–B3);
- listen = многократное впечатление знака в **свой** слой;
- babble = readout активного слоя из digest/grid.

**Не делает (не её зона):**

- грамматика-норматив как encyclopedia (Exp J на диске — **вход** для listen, не память);
- «объяснить пользователю падеж»;
- замена LLM.

## Порядок в общей архитектуре

```text
ССС (знаки в цилиндре)  →  listen / babble / correct
        ↓ hub E: (позже)
Первая СС (образ/счёт)   →  Exp L
        ↓
CEN/SN                   →  маршрутизация слоёв, не grep по JSON
```
