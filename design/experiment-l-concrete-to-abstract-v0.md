# Experiment L: от конкретного к абстрактному (схемы + «взгляд»)

**Status:** design (после выпуска Exp J)  
**Date:** 2026-05-29  
**Logical layer (F0…F2):** [`f0-math-logical-layer-v0.md`](f0-math-logical-layer-v0.md)  
**Depends on:** [Exp J complete](experiment-j-language-complete-v1.md) (речь/текст), [J0 literacy](experiment-j0-russian-literacy-v1.md)  
**Paused until J done:** [Exp K](experiment-k-code-emit-v0.md) (C#), другие предметы

## North star

> Агент **узнаёт одну и ту же схему** в разных оболочках: палочки, точки, картинки букваря, слово — и **называет/связывает** её через общие `concept_id` на поле, без угадывания «по пикселям как в CLIP с нуля».

**Абстрактное мышление здесь** = перенос структуры, не художественный вкус:

- «два» = `||` = две палочки на картинке = слово **два** = `math.two`;
- «сложить группы» = `| + |` = та же операция для яблок и для палочек;
- **корова** на картинке = `vis.animal.cow` ↔ **корова** в тексте = `lang.word.cow` (букварь).

## Почему после языка (J), а не вместо

| Без J (речь) | С J |
|--------------|-----|
| Картинка → метка без переноса | Картинка **привязана к слову и схеме** уже в поле |
| «Похоже на корову» | «Это **корова**; так же зовут животное с рогами…» (claim) |
| Счёт «вслепую» | «Два» сначала **назвали**, потом **показали** |

Как у ребёнка: **сначала элементы языка** (буква → слог → слово в цилиндре, см. [`bukvar-text-modality-v0.md`](bukvar-text-modality-v0.md)), потом фразы и коррекция, потом картинки L4 **к уже знакомым словам**, потом операции (L0 math).

## Две модальности, один каркас

```text
         lang.*  (J / J0)          math.*  (L0 символы)
              \                    /
               \                  /
                ▼                ▼
            concept_id hub  (C: / V: / E:)
                ▲                ▲
               /                  \
              /                    \
         vis.*  (L2 картинки)    операторы +, =, …
```

| Префикс | Модальность | Пример token / id |
|---------|-------------|-------------------|
| `lang.` | слово, перефраз | `lang.word.cow`, «корова» |
| `math.` | схема, число, операция | `math.two`, `math.add` |
| `vis.` | визуальный якорь | `vis.animal.cow`, `vis.scene.farm` |
| `E:` | ребро графа | `E:vis.animal.cow\|lang.word.cow` |

**Не кладём сырые пиксели в NCA v0.** Картинка → **файл + concept_id** в bundle (как claim с `image_ref`), на поле — токены `V:` и связи `E:` с `lang.*` / `math.*`.

## Лестница L0–L4 (куррикулум)

### L0 — схемы без картинок (символы на поле)

**Цель:** абстракция «два», «сложить» **до** CV.

| Урок | Конкрет | Абстракция (claim) |
|------|---------|-------------------|
| 1 | `\|` | `math.one` |
| 2 | `\|\|` | `math.two` |
| 3 | `\| + \|` → `\|\|\|` | `math.add`, «склеить группы» |
| 4 | сравнение `\|\|` vs `\|\|\|` | `math.compare.more` |

- KB: `kb-math-concrete-schemas-v1.md` (lab / agent-notes).
- Bench: запрос «сколько палочек» → `math.two` (текст/символ), read@1.

### L1 — язык ↔ схема (мост из J0)

- Те же `math.*`, что в L0, плюс literacy-кластеры: «два числа», «сложи» → **не путать** с «два предмета».
- Claims: «**два** — слово для `math.two`», «**сложить** — как `math.add` для групп».
- Bench: перефраз RU → `math.two` или `lang.word.two`.

### L2 — «взгляд» v0 (картинки к concept_id)

**Цель:** grounding — картинка **не** новая память с нуля, а **якорь** к уже известному слову/схеме.

| Тип картинки | Примеры | concept_id |
|--------------|---------|------------|
| Счёт / палочки | одна/две/три палочки, слияние | `vis.count.sticks_N` → `math.N` |
| Слияние групп | две кучки → одна | `vis.op.merge` → `math.add` |

Формат bundle:

```json
{
  "concept_id": "vis.count.sticks_2",
  "text": "Две вертикальные палочки (иллюстрация).",
  "image_ref": "examples/exp_l_vision/sticks/sticks_2.svg",
  "links": ["math.two", "lang.word.two"]
}
```

Bench **vis@1:** по пути/подписи запроса «картинка две палочки» → top claim содержит `math.two` или `vis.count.sticks_2` + ребро к `lang`.

### L3 — перенос (абстракция в смысле Пиаже)

- Обучающие: палочки, точки, яблоки (разные `vis.*`).
- Тест: **новая** картинка (три кружка) → тот же `math.three`, не виденная в train.
- Метрика **transfer@1** ≥ 0.7 на маленьком closed-set (10–20 классов), не ImageNet.

### L4 — букварь (как в школе: корова, овца, пчела…)

**Цель:** большой **закрытый** набор картинок ↔ слов — «первый словарь мира».

| Категория | Примеры слов | Примечание |
|-----------|--------------|------------|
| Домашние животные | корова, овца, коза, лошадь, курица | `vis.animal.*` |
| Дикие / лес | волк, медведь, лиса, заяц | позже |
| Насекомые | пчела, бабочка, муравей | |
| Природа | дерево, солнце, дождь | `vis.nature.*` |
| Люди/действия | мама, идти, спать | после животных |

**Объём v1 (оценка):** 50–80 пар слово+картинка; v2 — 200+ как настоящий букварь.

Структура KB:

- `kb-bukvar-ru-animals-v1.md` — таблица: слово, `-а` окончание, картинка, короткий claim («даёт молоко» — опционально, **фактология для детей**).
- Каждая строка → `concept_id` + `image_ref` + ребро `E:vis.*|lang.word.*`.

Bench **bukvar@1:**

- показали `cow.png` / запрос «что на картинке» → `answer_text` с **корова** + `vis.animal.cow`;
- запрос «пчела» → retrieve картинку/claim с `vis.animal.bee`;
- перефраз: «животное даёт мёд» → `пчела` (только если есть такой claim — не магия).

**Педагогика:** как букварь — **много однотипных карточек**, один принцип «картинка = слово», без грамматики вперемешку (грамматика остаётся в J).

## Latency contract (почему это остаётся **мс**, не секунды)

**Сейчас (Exp J, `--from-field`):** типичный запрос **7–12 ms** end-to-end (decode grid + match claims + `answer_text`); первый после холодного старта ~25 ms. См. `report_grammar_recall.json`, `report_write.json`.

| Слой | В hot path? | Порядок времени |
|------|-------------|-----------------|
| `load field_state` + decode 64×64 | ✅ | ~1–5 ms |
| `_match_claims` по union (~250–500 claims) | ✅ | ~1–5 ms (линейный скан, CPU) |
| `articulation_grammar_v0` | ✅ | &lt;1 ms |
| **NCA repair** | ❌ только bench/offline | ~секунды |
| **LLM / CLIP на запрос** | ❌ только ingest / опциональный probe | сеть/ GPU |
| Кодирование PNG в runtime | ❌ | ingest → `concept_id` |

**Exp L не меняет эту формулу:** букварь на 80–200 слов = больше claims, оценка **15–40 ms** на том же hot path (всё ещё **&lt;100 ms**). Цель north star: **p95 &lt; 50 ms** локально, **&lt;200 ms** с запасом на IDE/диск.

Что **убьёт** «разбили в хлам» vs «обман»:

- ✅ **Разбили:** тот же пайплайн, что J, но multimodal память (слово + картинка + схема) за **один проход поля**.
- ❌ **Обман:** если на каждый запрос гонять ViT/LLM — это другой продукт, в L **запрещено** на hot path.

**Правило v0:** новая картинка в проде = уже есть `vis.*` в store; запрос «что на картинке» идёт как **текст + id** (`image_ref` / подпись в query), не raw CNN inference.

## CV на своей архитектуре (не только «чужой CLIP»)

**Да** — Computer Vision можно собирать **на том же субстрате**, что текст: **64×64 поле + локальные правила + z-фазы**, не обязательно внешний тяжёлый encoder на hot path.

### Два уровня (оба «наши»)

| Уровень | Что на поле | Когда | Hot path |
|---------|-------------|-------|----------|
| **L2a — semantic V:** | токены `V:vis.animal.cow`, рёбра к `lang.*` | ingest картинки → codec | **мс** (как J) |
| **L2b — CA vision:** | **каналы клетки** несут патч/признак; NCA **чинит** и **связывает** локально | train на тайлах картинок | **мс–десятки ms** (decode + опц. 1 rollout) |

L2a — букварь и палочки **быстро**. L2b — «настоящий» CA-CV, к которому идём, когда L2a стабилен.

### Как L2b ложится на уже существующее

```text
z=0 encode     картинка → патчи на DMN (не «вся ImageNet», а 32×32 тайлы, ghost)
z=1 dmn_repair windowed NCA (уже есть train_dmn_nca_windowed.py)
z=2 digest     визуальный digest → SN (как текстовый digest)
z=3 gate       → CEN: name / count / match
```

- **Тайлы + ghost** ([`windowed-field-and-planner-v0.md`](windowed-field-and-planner-v0.md)) — естественный масштаб для **локального** зрения (фрагмент с коровой, две палочки в crop).
- **NCA `UpdateRule`** уже многоканальный (`channel_n`) — можно выделить каналы под **visual feature** + discrete tokens.
- **Не нужен** отдельный «мозг CV»: тот же DMN/SN/CEN, другой codec на z=0.

### Codec vision v0 (идея)

| Вход | На grid |
|------|---------|
| SVG/PNG 32×32 или crop | несколько **continuous** каналов (яркость, edge sobel — уже есть в train util) |
| Класс / слово | дискретные `V:` + `C:lang.word.cow` |
| Пара «картинка+слово» | ребро `E:` в encode |

Ingest: один раз прогнать encode + записать в `field_state`.  
Query «что на картинке»: **decode** (+ при необходимости **короткий** rollout repair, как bench, не 100 шагов в проде).

### Latency при CA-CV

| Режим | Оценка |
|-------|--------|
| Только decode (память уже на поле) | **~10–30 ms** (как сейчас + чуть больше каналов) |
| decode + **K=1..3** repair steps | **+5–20 ms** на GPU — всё ещё **&lt;100 ms** |
| Полный train-time rollout (50+ steps) | только offline |

Цель: **p95 &lt; 50 ms** с K≤3 repair; **&lt;200 ms** с запасом.

### Чего CA-CV **не** обещает в v0

- open-set ImageNet в одном 64×64 без тайлов;
- замена языка картинкой;
- «понял абстракцию» только из пикселей без `lang.*` / `math.*`.

### Порядок

```text
J выпуск  →  L2a (V: токены, букварь, мс)  →  L2b (CA vision на тайлах)  →  L3 transfer
```

Cosmos-scale video — отдельный контур ([`casa-cosmos-mapping-v0.md`](casa-cosmos-mapping-v0.md)); **букварь + палочки** — наш lab-scale CA-CV.

## Архитектура в CASA

```text
Image file (SVG/PNG)
    → ingest: image_ref + vis.concept_id + edges to lang.*
    → bundle → union field (vision-agent-lab-v0 или language+vision store)
    → SN: vis salience vs lang (модальность по префиксу)
    → CEN: describe_image | name_object | count_objects
    → articulation vision v0: «На картинке … (по памяти …)»
```

| Компонент | v0 | v1+ |
|-----------|----|-----|
| Codec | `V:` + `E:` cross-modal | patch hash / лёгкий encoder → **concept** (не grid пикселей) |
| Store | `examples/agent-stores/vision-agent-lab-v0` | union с language после стабильного J |
| Train | NCA на **токенах** vis+math+lang | windowed, те же тайлы |
| MCP | опционально webcam → digest как **наблюдение** | не замена `image_ref` |

**Principle:** hot path остаётся **поле + claims**; тяжёлый CV — offline при ingest (генерация SVG, иллюстрации, букварь).

| Phase | Содержание | Gate |

## Пример: палочки → корова (одна цепочка)

```text
L0  "|" "|"  →  math.two
L1  "две палочки"  →  math.two
L2  [SVG две палочки]  →  vis.count.sticks_2  —E—  math.two, lang.word.two
L4  [SVG корова]  →  vis.animal.cow  —E—  lang.word.cow
     запрос: "что на картинке"  →  answer_text: "Корова (животное на ферме)."
```

Счёт и букварь — **один механизм**, разный контент.

## Non-goals (v0)

- Open-vocabulary vision (любое фото из интернета).
- Сырые пиксели в 64×64 NCA grid.
- Замена языка картинками («смотреть вместо читать»).
- OCR всего букваря как единственный канал (текст на картинке — отдельно, позже).
- C#, код, compile — по-прежнему после J и базового L.
