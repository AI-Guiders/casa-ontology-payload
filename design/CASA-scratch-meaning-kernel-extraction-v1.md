## Зачем (одним абзацем)

Хочу оформить понятийную сеть + валидатор + reasoning-слой как **самостоятельную открытую
библиотеку** и написать на её базе 1–2 исследовательские статьи (бенчмарк опасных классов
polarity/quantity/unit + кросс-язычная проверка правил с proof-trees; план и каркасы — в
`articles/research/`). Коммерческой цели нет; цель — исследовательский вес и цитируемый
артефакт. Для CASA это тоже плюс: публикация ссылается на проект, методология (честный триаж,
потолок покрытия, reality-check) получает внешнюю видимость, а кернел — внешних пользователей.

## Ключевой принцип: форк-копия, не зависимость

- **В CASA не меняется ни одна строка.** Извлечение = копирование модулей в новый репозиторий;
  `casa/curriculum` продолжает жить как жил.
- Новый репозиторий **не** становится зависимостью CASA, и CASA **не** становится зависимостью
  библиотеки. Никакой связанности релизных циклов.
- Синхронизация — ручная и по необходимости, направление по умолчанию CASA → библиотека
  (кернел маленький и стабильный; для статьи нужна зафиксированная версия в любом случае).
- Шов команды по ADR-0085 (`concept.*` / `lemma.*` / agent-concept-graph) **не затрагивается**:
  извлекается лабораторный harness (см. ниже), а не store-сторона.

## Что извлекается (проверено по импортам всех 37 модулей curriculum)

| Слой | Модули | Зависимость от CASA |
|---|---|---|
| Чистое ядро | `reasoning`, `equivalence`, `situation`, `states`, `attributes`, `quantity` | **нулевая** — только импорт-пути |
| Тонкий шов | `parse`, `translate`, `concept_net`, `situation_store`, `software_domain` | 4 функции (см. «Технический шов») |
| Бутстрап | `world` (переписывается: JSON-загрузка вместо `ensure_prisms`/`ingest_math_bundle`) | переписывается |
| Генерация | `roundtrip`, `compose`, `sentence`, `clause`, `render`, `ask` | тот же шов |
| Замеры | `reality_check` (+ режим `--ceiling`) | только импорт-пути |
| Данные | `lab/curriculum/concept-net-{base,wide}-v1.json`, `ru-rules-v1.json`, `en-rules-v1.json` | копия как есть |
| Тесты | ~15 файлов (`test_reasoning`, `test_conditional`, `test_forward_chain`, `test_value_mutex`, `test_states`, `test_equivalence`, `test_parse`, `test_situation`, `test_concept_net*`, `test_roundtrip`, `test_ask`, …) | копия — страховка извлечения |

**Что НЕ извлекается:** агентский стор и всё living-agent (prisms, NCA, sleep/hippo, chat,
converse), учебная машинерия (`teach`/`loop`/`staging`/`metrics`, held-out гейт),
`glossary` (сон/консолидация), `demo_repl`, store-сторона Concept Zone
(`concept_built_in.py` и т.п.).

## Технический шов (почему это безболезненно)

Вся связь парсера/онтологии с CASA — четыре функции из `casa.prisms.memory`:
`memory_lattices`, `decode_f0_lattice`, `strengthen_graph_edge`, `weaken_graph_edge`.
Они работают с обычными словарями (`lattice["cells"]` — список списков строк, декодирование =
подсчёт голосов), без стора, NCA и персистентности. `world.py` сам фиксирует (комментарий к
ADR-0083 §5): латтис `schema-math` здесь — **lab scaffolding**, не модель стора.

В библиотеке эти четыре сигнатуры закрываются **шимом ~50–100 строк** поверх простого
мультимножества рёбер `{"E:src|rel|dst": вес}`. Остальной код меняется только в импорт-путях.

Открытый технический пункт: `build_meaning_state` подмешивает bundle
`lab/exp_l/kb-math-concrete-schemas-l0.bundle.v1.json` (names-рёбра слов). При извлечении —
либо копия bundle, либо (чище) перенос имён явно в JSON онтологии. Решится по месту, на
поведение CASA не влияет.

- Где хостить — **моё предложение: личный аккаунт (dmitrat)**. Плюсы: не создаёт команде
  обязательств по поддержке и внешним issues/PR; атрибуция CASA/AI-Guiders в README всё равно
  явная (см. выше). Если команда предпочитает org AI-Guiders — обсуждаемо.

## Статьи и авторство

- Статья 1 (бенчмарк, главная): идея сети и валидаторное направление — моё, кернел и замеры
  делались совместно с ассистентом на ваших принципах (held-out, честные числа). Предлагаю
  обсудить состав авторов/благодарностей **до** появления текста; моя позиция по умолчанию —
  благодарность проекту CASA + поимённо тем, кто захочет соавторство и вложится в текст/замеры.
- Статья 2 (reasoning-слой) — аналогично.
- В обеих статьях CASA упоминается как проект-источник (это бесплатная видимость проекта);
  но статьи **не** заявляют ничего от имени команды о living-agent направлении.
