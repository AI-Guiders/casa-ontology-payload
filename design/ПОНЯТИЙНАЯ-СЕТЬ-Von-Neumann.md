# Понятийная сеть (affordance/type grounding) — POC

Документ для команды. Идея Дмитрия: у объектов есть небольшое число **адекватных
применений** (аффордансов). «Яблоко» — физический предмет (позиционируется) и еда
(съедобно). «Стол» — предмет и поверхность (на нём можно располагать). «Яблоко на столе»
тогда **валидируется** по этим аффордансам, и карта связей **одинакова для всех языков**.

POC на ветке `feat/conceptual-network`: `casa/curriculum/concept_net.py`,
данные `lab/curriculum/concept-net-v1.json`, тест `tests/test_concept_net.py`.

## Почему это родное для CASA
Всё на той же подложке рёбер, что и язык (teach → рёбра в поле → held-out гейт → ablation):
- `isa` — таксономия с наследованием: `lex.apple|isa|fruit`, `fruit|isa|food`, `fruit|isa|physical_object`.
- `affords` — способности на типе: `food|affords|edible`, `physical_object|affords|positionable`, `support|affords|support_surface`.
- ограничения отношений: `on|arg1|positionable`, `on|arg2|support_surface`.

Аффордансы концепта = объединение `affords` по его `isa`-замыканию → **наследуются**.
Кросс-язычность бесплатна: типы висят на концепте, а `concept|names|word` (глоссарий)
ведёт к словам любого языка. Поэтому «яблоко» и «apple» именуют один концепт → одна карта.

## Что показывает POC
```
affordances(apple) = {edible, positionable}
affordances(table) = {positionable, support_surface}

on(яблоко, стол)   = True      on(apple, table) = True     (одна карта, два языка)
on(стол, яблоко)   = False     (у яблока нет support_surface)
on(идея, стол)     = False     (идея не positionable — категориальная ошибка)
eat(человек, яблоко) = True     eat(яблоко, человек) = False (яблоко не agent)
in(яблоко, коробка)  = True
on(банан, стул)      = True     ← НЕвиданная пара, валидна через наследование
```

**Гейт** (`gate_concept_net`): held-out сочетания валидны через наследование (1.0);
негативный контроль — категориальные ошибки отклоняются; ablation `affords`-рёбер
ломает валидацию (доказывает, что проверка идёт из поля, а не из Python).

## Чем это ценно
- **Смысловой мост между языками** — карта одна, имена ведут к любому языку. Это и есть
  тот «слой смысла», который в языковой работе назывался потолком.
- **Защита от бессмыслицы без галлюцинаций** — типовая проверка никогда не назовёт
  `идея на столе` валидным; LLM такое не гарантирует.
- **Обобщение под гейтом** — новые объекты наследуют аффордансы; пары проверять не нужно.

## Честные границы
- Онтология **курируется** (авторская), не индуцируется из текста — индукция аффордансов
  это отдельная большая задача (дистрибутивная семантика).
- Это проверка **типов/аффордансов**, не физика и не прагматика мира.
- Масштабировать в **домен** (физические предметы; медицинская терминология Norav), а не в
  открытую житейскую онтологию (проблема Cyc — огромная и хрупкая).

## Базовая онтология (~280 понятий)
`scripts/build_concept_net.py` → `lab/curriculum/concept-net-base-v1.json`,
загрузка одним вызовом `teach_concept_net(state, lat, data)`, тест `test_concept_net_base.py`.
282 понятия в 21 листовой категории (люди, животные, фрукты/овощи/еда/жидкости, мебель,
посуда-контейнеры, здания/места, одежда, транспорт, инструменты, **детали**, части тела,
растения, природа, небесное, **вещества/материалы**, документы, абстракции) под **11
отношениями**. Все заземлены (0 «сирот»), аффордансы наследуются по категориям, gate зелёный.

**Два рода отношений:**
- *Типо-проверяемые* (по аффордансам, обобщают через наследование): `on/in/eat/drink/wear/
  ride/read/use` + `at` (локация: arg2 даёт `location`), `has` (владение: arg1 `agent`,
  arg2 `ownable`), `made_of` (материал: arg2 `material`).
- *Мереология* `has_part` (часть-целое) — утверждается фактами и **наследуется по типу**:
  `vehicle has_part колесо` → и машина, и велосипед имеют колесо; `lex.car has_part двигатель`
  → у машины есть, а у **велосипеда нет** (`has_part(велосипед,двигатель)=False`). `parts_of`
  перечисляет части. `человек has_part рука`, `дом has_part окно`, `дерево has_part лист`.

Пересобрать:
```
python scripts/build_concept_net.py --out lab/curriculum/concept-net-base-v1.json
```
Консоль (`chat-en.cmd`): команда `val <rel> <x> <y>` — `val on яблоко стол` → valid,
`val eat собака камень` → invalid, кросс-язычно (`val on apple table`).

Разрешение слова в концепт предпочитает **типизированный** концепт (с `isa`-ребром), так
что при слиянии с большим словарём `мясо` ведёт к `lex.meat` (в онтологии), а не к
синониму без типа.

## Заземлённая генерация (сеть × генератор)
`casa/curriculum/grounded.py`, тест `test_grounded.py`. Смысловая тройка проверяется сетью
**до** порождения — бессмыслица отклоняется, а не озвучивается. Глагол отображается в
отношение (`VERB_RELATION`: читать→read, есть→eat, …), `meaningful()` валидирует,
`guarded_clause()` валидирует и порождает на обоих языках или отказывает с причиной.
```
студент читать книга → "The student reads the book." / «Студент читает книгу.»
стол    читать книга → отказ: стол не агент (missing:agent)
человек есть   камень → отказ: камень несъедобен (missing:/edible)
девочка любить книга → порождает (у «любить» нет известного ограничения → unconstrained)
```
Отказ только когда сеть ЗНАЕТ, что сочетание неверно; неизвестные глаголы проходят.
Кросс-язычно. Консоль: `g студент читать книга`.

## Смысловой граф (карта связей)
`relation_map(rel, x, y)` — карта одной связи: два узла-концепта (типы, аффордансы, имена
на обоих языках) + типизированное проверенное ребро. `meaning_graph(triples)` — **граф из
многих связей**: «яблоко на столе у окна» = `on(apple,table)` + `near(table,window)` → 3
узла, 2 ребра. Узлы дедуплицируются по концепту; каждое ребро валидируется; одно
бессмысленное ребро помечает весь граф невалидным. Граф **байт-идентичен** для RU и EN
входа (живёт на концептах). `render_map`/`render_graph` — текстовый вид; консоль: `map`,
`graph on яблоко стол ; near стол окно`.

## Отпечаток ситуации (numeric, язык-независимый, вложенный)
`casa/curriculum/situation.py`, тест `test_situation.py`. Граф — это множество рёбер, поэтому
у него нет порядка слов. `fingerprint(graph)` даёт канонический ключ + **стабильный
целочисленный id** (отпечаток контекста) + аддитивный вектор-мешок рёбер.
- **Перефразировки → один id:** «лежит/стоит/находится/на» (через `normalize_relation`),
  любой порядок, и язык — `fp(лежит яблоко стол) == fp(на яблоко стол) == fp(on apple table)`.
- **Вложенность:** `contains(outer, inner)` — под-ситуация это под-множество рёбер, поэтому
  `fp("яблоко на столе") ⊆ fp("яблоко на столе у окна")`. Ситуации образуют частичный
  порядок (решётку ситуаций).
- **Похожесть:** `similarity` (Жаккар по рёбрам). Отличие от эмбеддингов LLM: точно и аудируемо.

Консоль: `fp лежит яблоко стол ; у стол окно`. Потолок честно: разбор свободного текста в
канонический граф (предикат→отношение, роли) — задача парсинга, сужается до домена.

## Разбор текста → граф (замыкание: текст → отпечаток)
`casa/curriculum/parse.py`, тест `test_parse.py`. Контролируемая клауза → канонический граф.
Честная рамка: правило-ориентированный разбор доменных клауз, не открытое понимание.
- **Локатив:** `[фигура] (глагол-связка)? ПРЕДЛОГ [опора] (ПРЕДЛОГ [опора])*` —
  «яблоко на столе», «яблоко лежит на столе», «на столе яблоко», «яблоко на столе у окна».
- **Переходное S-V-O:** `[подлежащее] ГЛАГОЛ [дополнение]` — «собака ест мясо», «студент читает книгу».
- Склонённые слова разрешаются по стему (`столе→стол→lex.table`, `рыбу→рыба→lex.fish`); разбор
  ведёт **только к понятиям онтологии** (с ребром `isa`), чтобы стем не утекал в синонимы
  большого словаря.

**Замыкание:** `parse яблоко лежит на столе` == `parse на столе яблоко` == `parse apple on
the table` → **один отпечаток ситуации**. Свободный текст (в рамках домена) → язык-независимый
численный отпечаток. Консоль: `parse <текст>`.

## Память ситуаций («видел ли я такую конфигурацию?»)
`casa/curriculum/situation_memory.py`, тест `test_situation_memory.py`. Хранит отпечатки и
ищет тремя способами (точная алгебра множеств над концептами, язык-независимо):
- `seen` — точное совпадение по id (видел ли точно эту ситуацию; для одно-рёберных клауз —
  инвариантно к перефразировке и языку).
- `recall_containing` — сохранённые ситуации, **включающие** запрос как под-ситуацию
  (запрос «яблоко на столе» находит сохранённое «яблоко на столе у окна»).
- `recall_similar` — ранжирование по перекрытию рёбер (Жаккар).

Запоминаются только **осмысленные** ситуации: граф без валидных рёбер (категориальная
ошибка) — не ситуация (`«кот ест рыбу»` отклоняется, т.к. рыба-животное несъедобна).
CASA-нативно: ключ — мешок рёбер отпечатка, метрика — перекрытие; точно и аудируемо в
отличие от непрозрачного векторного поиска. Консоль: `remember <текст>`, `recall <текст>`.

**Персистентность на поле** (`situation_store.py`, `test_situation_store.py`): отпечатки
минтятся рёбрами на латтисе (`sit.<id>|edge|on(lex.apple,lex.table)`), поэтому память живёт
в `field_state` и переживает сессии — как всё остальное знание. `persist_situation`
кладёт на поле, `load_memory` восстанавливает структуру для recall, `forget_situation`
убирает. Никакой отдельной БД — та же подложка (strengthen/decode/weaken).

## Структурная аналогия («эта ситуация как та»)
`casa/curriculum/analogy.py`, тест `test_analogy.py`. Две ситуации аналогичны, если есть
согласованная биекция их концептов, превращающая одно множество рёбер в другое (те же
отношения, отображённые концы) — структурное отображение (Gentner), детерминированно.
`«кот на стуле» ~ «яблоко на столе»` → `{cat:apple, chair:table}`, при нуле общих концептов.
По умолчанию отображаемые концепты типо-совместимы (cat~apple — оба physical_object;
cat~idea — нет). `recall_analogous` находит сохранённые ситуации той же структуры (реляционный
поиск поверх памяти). Разные отношения → не аналогичны. Консоль: `like кот на стуле`.

## Перевод через смысл (текст → граф → текст)
`casa/curriculum/roundtrip.py`, тест `test_roundtrip.py`. Соединяет парсер (текст→граф) и
реализатор (граф→текст): «перевод с русского на русский» Дмитрия. Одна формулировка
нормализуется в перефраз на том же языке, а переключатель целевого языка превращает round-trip
в перевод — всё через один язык-независимый граф:
```
«яблоко лежит на столе» = «на столе яблоко» = «apple on the table»
   → RU «Яблоко на столе.»   EN "The apple is on the table."
«студент читает книгу» → RU «Студент читает книгу.» EN "The student reads the book."
```
Реализатор склоняет по падежу отношения (на/в → предложный «на столе»; у → родительный
«у окна», правило по роду-окончанию) и переиспользует генераторы для переходных клауз.
Консоль: `rt <текст>`. Потолок: доменные клаузы; иррегулярные глаголы (есть/пить) — к лемме.

**Встроено в основной чат** (`casa.cli chat`): команда `/meaning <фраза>` запускает round-trip
через понятийную сеть прямо в чате (`build_meaning_state` лениво строит состояние при первом
вызове).

**Глубокая маршрутизация** (`casa/curriculum/converse.py`, `test_converse.py`): если реплика —
**чистая доменная клауза** (`answer_clause`), агент отвечает через понятийную сеть ДО
статистического движка — валидирует ситуацию, подтверждает нормализованный смысл (RU+EN),
отмечает похожие запомненные ситуации и сохраняет её; на категориальной ошибке объясняет, почему
так нельзя. Строго гейтировано: дешёвый пред-фильтр `looks_domain` (короткая строка с предлогом/
глаголом) → проверка «все слова известны» → парс. Всё прочее (`привет`, `у меня нет времени`,
`расскажи про…`) проваливается в обычный движок. Управление: флаг `--no-route`, команда
`/route on|off`; по умолчанию включено на ветке. Диалоговый движок не тронут (маршрутизатор
`continue`-ит до него) — обратимо.

## Масштаб: широкая онтология (~2.5к понятий)
`scripts/build_concept_net_wordnet.py` → `lab/curriculum/concept-net-wide-v1.json` (build-time:
`nltk`+`wordnet`). Поверх курируемого ядра (тонкие аффордансы) накладывается большой
авто-классифицированный словарь: русские существительные из OpenRussian (CC BY-SA), категория
каждого — по доминирующему **супер-смыслу WordNet** (`noun.animal→animal`, `noun.food→food`,
`noun.artifact→artifact`…). Ядро сохраняет точные аффордансы (мебель→несущая, транспорт→ездить);
слой WordNet — грубые аффордансы уровня супер-смысла. **2483 понятия**, валидация ядра не
страдает (gate 22/22). Разрешение склонённых слов улучшено (наибольший общий префикс →
кратчайшая лемма: «столе»→«стол», а не «столб»), синонимы разрешаются в более типизированный
концепт (мясо→meat, не flesh). Консоль и `/meaning` используют широкую онтологию.
