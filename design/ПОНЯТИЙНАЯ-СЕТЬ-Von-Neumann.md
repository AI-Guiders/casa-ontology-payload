# Понятийная сеть (affordance/type grounding) — POC

Документ для команды. Идея Дмитрия: у объектов есть небольшое число **адекватных
применений** (аффордансов). «Яблоко» — физический предмет (позиционируется) и еда
(съедобно). «Стол» — предмет и поверхность (на нём можно располагать). «Яблоко на столе»
тогда **валидируется** по этим аффордансам, и карта связей **одинакова для всех языков**.

POC на ветке `feat/conceptual-network`: `casa/curriculum/concept_net.py`,
данные `lab/curriculum/concept-net-v1.json`, тест `tests/test_concept_net.py`.

## Почему это родное для CASA
Всё на той же подложке рёбер, что и язык (teach → рёбра в поле → held-out гейт → ablation):
- `isa` — таксономия с наследованием: `lex.apple|isa|fruit`, `fruit|isa|food`, `fruit|isa|physical_object`.
- `affords` — способности на типе: `food|affords|edible`, `physical_object|affords|positionable`, `support|affords|support_surface`.
- ограничения отношений: `on|arg1|positionable`, `on|arg2|support_surface`.

Аффордансы концепта = объединение `affords` по его `isa`-замыканию → **наследуются**.
Кросс-язычность бесплатна: типы висят на концепте, а `concept|names|word` (глоссарий)
ведёт к словам любого языка. Поэтому «яблоко» и «apple» именуют один концепт → одна карта.

## Что показывает POC
```
affordances(apple) = {edible, positionable}
affordances(table) = {positionable, support_surface}

on(яблоко, стол)   = True      on(apple, table) = True     (одна карта, два языка)
on(стол, яблоко)   = False     (у яблока нет support_surface)
on(идея, стол)     = False     (идея не positionable — категориальная ошибка)
eat(человек, яблоко) = True     eat(яблоко, человек) = False (яблоко не agent)
in(яблоко, коробка)  = True
on(банан, стул)      = True     ← НЕвиданная пара, валидна через наследование
```

**Гейт** (`gate_concept_net`): held-out сочетания валидны через наследование (1.0);
негативный контроль — категориальные ошибки отклоняются; ablation `affords`-рёбер
ломает валидацию (доказывает, что проверка идёт из поля, а не из Python).

## Чем это ценно
- **Смысловой мост между языками** — карта одна, имена ведут к любому языку. Это и есть
  тот «слой смысла», который в языковой работе назывался потолком.
- **Защита от бессмыслицы без галлюцинаций** — типовая проверка никогда не назовёт
  `идея на столе` валидным; LLM такое не гарантирует.
- **Обобщение под гейтом** — новые объекты наследуют аффордансы; пары проверять не нужно.

## Честные границы
- Онтология **курируется** (авторская), не индуцируется из текста — индукция аффордансов
  это отдельная большая задача (дистрибутивная семантика).
- Это проверка **типов/аффордансов**, не физика и не прагматика мира.
- Масштабировать в **домен** (физические предметы; медицинская терминология Norav), а не в
  открытую житейскую онтологию (проблема Cyc — огромная и хрупкая).

## Базовая онтология (~280 понятий)
`scripts/build_concept_net.py` → `lab/curriculum/concept-net-base-v1.json`,
загрузка одним вызовом `teach_concept_net(state, lat, data)`, тест `test_concept_net_base.py`.
282 понятия в 21 листовой категории (люди, животные, фрукты/овощи/еда/жидкости, мебель,
посуда-контейнеры, здания/места, одежда, транспорт, инструменты, **детали**, части тела,
растения, природа, небесное, **вещества/материалы**, документы, абстракции) под **11
отношениями**. Все заземлены (0 «сирот»), аффордансы наследуются по категориям, gate зелёный.

**Два рода отношений:**
- *Типо-проверяемые* (по аффордансам, обобщают через наследование): `on/in/eat/drink/wear/
  ride/read/use` + `at` (локация: arg2 даёт `location`), `has` (владение: arg1 `agent`,
  arg2 `ownable`), `made_of` (материал: arg2 `material`).
- *Мереология* `has_part` (часть-целое) — утверждается фактами и **наследуется по типу**:
  `vehicle has_part колесо` → и машина, и велосипед имеют колесо; `lex.car has_part двигатель`
  → у машины есть, а у **велосипеда нет** (`has_part(велосипед,двигатель)=False`). `parts_of`
  перечисляет части. `человек has_part рука`, `дом has_part окно`, `дерево has_part лист`.

Пересобрать:
```
python scripts/build_concept_net.py --out lab/curriculum/concept-net-base-v1.json
```
Консоль (`chat-en.cmd`): команда `val <rel> <x> <y>` — `val on яблоко стол` → valid,
`val eat собака камень` → invalid, кросс-язычно (`val on apple table`).

Разрешение слова в концепт предпочитает **типизированный** концепт (с `isa`-ребром), так
что при слиянии с большим словарём `мясо` ведёт к `lex.meat` (в онтологии), а не к
синониму без типа.

## Заземлённая генерация (сеть × генератор)
`casa/curriculum/grounded.py`, тест `test_grounded.py`. Смысловая тройка проверяется сетью
**до** порождения — бессмыслица отклоняется, а не озвучивается. Глагол отображается в
отношение (`VERB_RELATION`: читать→read, есть→eat, …), `meaningful()` валидирует,
`guarded_clause()` валидирует и порождает на обоих языках или отказывает с причиной.
```
студент читать книга → "The student reads the book." / «Студент читает книгу.»
стол    читать книга → отказ: стол не агент (missing:agent)
человек есть   камень → отказ: камень несъедобен (missing:/edible)
девочка любить книга → порождает (у «любить» нет известного ограничения → unconstrained)
```
Отказ только когда сеть ЗНАЕТ, что сочетание неверно; неизвестные глаголы проходят.
Кросс-язычно. Консоль: `g студент читать книга`.

## Смысловой граф (карта связей)
`relation_map(rel, x, y)` — карта одной связи: два узла-концепта (типы, аффордансы, имена
на обоих языках) + типизированное проверенное ребро. `meaning_graph(triples)` — **граф из
многих связей**: «яблоко на столе у окна» = `on(apple,table)` + `near(table,window)` → 3
узла, 2 ребра. Узлы дедуплицируются по концепту; каждое ребро валидируется; одно
бессмысленное ребро помечает весь граф невалидным. Граф **байт-идентичен** для RU и EN
входа (живёт на концептах). `render_map`/`render_graph` — текстовый вид; консоль: `map`,
`graph on яблоко стол ; near стол окно`.
