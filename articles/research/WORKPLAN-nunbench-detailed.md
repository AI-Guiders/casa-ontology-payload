### W1. Данные: EMEA + KDE4 en-es (неделя 1) `[А, отбор форм — Д]`

- **W1.1** Скачать OPUS EMEA en-es + KDE4 en-es в `.scratch/opus/` (по образцу существующего
  KDE4 en-ru). (S)
  *Приёмка:* файлы Moses-формата лежат локально, счётчики строк записаны.
- **W1.2** Фильтр-отбор EMEA: длина ≤ ~20 токенов, содержит отношение-кандидат (число+единица /
  отрицание / глагольная инструкция), дедупликация, чистка разметки. Цель ≥300 «этикеточных»
  пар (дозировки, противопоказания, инструкции по применению, условия хранения). (M)
  *Приёмка:* `emea-pairs-v0.jsonl` с полями `{id, en, es, section_hint}`; выборка из 30 пар
  просмотрена глазами `[Д]` — пары действительно переводы друг друга.
- **W1.3** Курируемый набор: перенести существующие контролируемые формы (RU/EN) + собрать
  ES-эквиваленты для них. (S→M)
  *Приёмка:* `curated-triples-v0.jsonl` `{id, en, es, ru, form_class}`.

### W2. ES-слой парсера (недели 1–2) `[А]`

Скоуп: **только парсинг** (равенство не требует генерации). Работать на текущей ветке
`feat/reasoning-layer` или отдельной `feat/es-layer` — решить при старте, отдельная чище.

- **W2.1** `lang`-параметр: `parse_graph(state, lattice, text, lang=None)` и `resolve_token(...,
  lang=None)`; `lang=None` = текущее поведение (обратная совместимость, все существующие тесты
  зелёные без правок). Фильтрация имён по языку при заданном `lang`. (M)
  *Решение внутри задачи:* как язык-тегировать names в lab-harness. Рекомендация: не менять
  формат рёбер `concept|names|lang.word.*`, а держать per-language наборы поверхностей в
  ontology-JSON (`names: {en:[], es:[], ru:[]}`) и строить из них языковые индексы при
  `build_meaning_state`. Не трогает командный шов ADR-0085 (это lab, не store).
  *Приёмка:* тест-омограф: «red» при `lang="en"` → concept.red (цвет), при `lang="es"` →
  concept.network (сеть) или честный отказ, если сети нет в онтологии; старые тесты зелёные.
- **W2.2** ES служебные слова в `parse.py`: предлоги (en/sobre/de/a/con/para), отрицание
  (no/nunca/sin), связка (es/está/son/están), сочинение (y/e), условие (si … entonces),
  артикли-пропуски (el/la/los/las/un/una), слова-числа (uno…diez). Единицы (ml/mg/g/l) —
  уже совпадают. (M)
  *Приёмка:* параметризованные тесты `test_parse_es.py`: локатив, транзитив, императив,
  отрицание, число+единица, состояние («el archivo está abierto»), координация, условие —
  каждый даёт граф, побайтно равный графу EN/RU-эквивалента.
- **W2.3** ES-имена концептов для скоупа бенчмарка: пройтись по концептам, реально встречающимся
  в W1.2/W1.3 (ожидаемо 200–400), сгенерировать ES-поверхности LLM-ассистированно, выборочная
  проверка. Формы прилагательных по роду/числу (rojo/roja/rojos/rojas) — как отдельные
  поверхности. Множественное -s/-es уже покрыто `_en_singulars`. (M)
  *Приёмка:* доля резолва токенов на EMEA-выборке измерена и записана (это вход в ceiling).
- **W2.4** ES-ветка в `equivalence.py`/`reasoning.py` — ожидаемо **ноль правок** (работают на
  канонических рёбрах), но прогнать и зафиксировать: кросс-язычные тесты EN↔ES↔RU
  (полярность/число/единица). (S)
  *Приёмка:* `test_equivalence_es.py` зелёный: «no abrir el archivo» ✗ «open the file»;
  «5 ml» ⚠unit «5 mg» кросс-язычно.

### W4. Генератор бенчмарка (неделя 2) `[А, верификация — Д]`

- **W4.1** Модуль инъекций (расширение `reality_check.py` или новый
  `casa/curriculum/benchmark.py`): по классам —
  `polarity` (удалить/добавить no/not/не; морфологические ловушки где есть),
  `quantity` (подмена цифры 5→50, ×10, перестановка разрядов; слова-числа dos→tres),
  `unit` (mg↔ml, mg↔µg, ml↔l). Инъекция всегда в ОДНУ сторону пары; мета фиксирует
  оригинал/замену/позицию. (M)
  *Приёмка:* генератор детерминирован (seed), каждая инъекция воспроизводима из мета.
- **W4.2** Контроли: (a) корректные пары как есть, (b) корректно-отрицающие обе стороны,
  (c) безопасные парафразы (перестановка слов, артикли) — не должны флагаться. (S)
- **W4.3** Схема датасета `nunbench-v0.1.jsonl`:
  `{id, src_lang, tgt_lang, src, tgt, label: equivalent|error, error_class: polarity|quantity|unit|null,
  injection: {side, original, replacement, char_span}|null, source: emea|curated,
  split: public|heldout, license, provenance}`. Плюс канарейки в heldout. (S)
- **W4.4** Верификация `[Д]`: просмотреть все polarity-инъекции (самый рискованный класс —
  двойное отрицание, sin+инфинитив) и выборку 10% остальных. (M, человеко-часы)
  *Приёмка:* заморозка v0.1: ~300–500 error-пар + ~столько же контролей; хэш файла записан.
- **W4.5 Smoke-test** (до заморозки): 1 модель × 50 пар — ранний сигнал, какой kill-сценарий
  реализуется; при необходимости скорректировать состав классов. (S)
- **W4.6 GATE 2 (15 июля):** датасет заморожен.

### W5. LLM-судьи (неделя 3) `[А]`

- **W5.1** Протокол: единый промпт (система: «судья эквивалентности перевода», ответ строго
  JSON `{verdict: equivalent|divergent|cannot_verify, class: ...|null, rationale}` — зеркало
  нашего триажа) + 1 альтернативная формулировка для чувствительности. Температура — дефолт
  провайдера; фиксировать модель+версию+дату. (S)
- **W5.2** Пайплайн прогонов: 3–4 модели (2 frontier + 1–2 открытые) × 5 прогонов × весь
  public-сплит; кэширование сырых ответов в JSONL (никогда не перезаписывать), ретраи,
  учёт стоимости. Оценка объёма: ~1000 пар × 5 × 4 = ~20k коротких вызовов — дни не нужны,
  бюджет умеренный; если упрёмся — 5 прогонов только на стабильность-подмножестве (500 пар). (M)
  *Приёмка:* `runs/raw/*.jsonl` полные; скрипт агрегации выдаёт метрики без ручных шагов.
- **W5.3** Кернел на том же датасете: те же метрики + coverage (доля ❓). (S)
- **W5.4** Метрики (единый скрипт `metrics.py` в репо бенчмарка):
  recall по классам, precision, FPR на контролях, **consistency@5** (доля пар с единогласным
  вердиктом по 5 прогонам), abstention rate, risk–coverage кривая, cost/latency. (M)

## Зависимости (критический путь)

```
W1.1 → W1.2 ─┬→ W3.2 (ceiling) → GATE 1
             └→ W4.1 → W4.4 → GATE 2 → W5.2 → W5.4 → GATE 3 → W6.2 → GATE 4 → W7
W2.1 → W2.2/W2.3 → W2.4 ──────────────↑ (нужны к W5.3 — кернел на датасете;
                                        частично к W3.1 — ES-маркеры отношений)
W6.1 — как можно раньше (формат влияет на объём текста)
W8.2 — до W6 (авторы на титуле)
```

Самая рискованная связка: **W2 (ES-слой) должен быть готов к началу недели 3** (W5.3).
Если W2 задерживается — W5.2 (LLM-прогоны) идёт по расписанию (от ES-парсера не зависит),
а кернел-строка таблицы добавляется последней; в предельном случае кернел меряется только
на EN/RU-частях + ES-подмножестве, которое успело покрыться — честно оговорить в тексте.
